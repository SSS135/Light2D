# assets-refresh gives no signal that recompilation is deferred while the Editor is in Play mode

`assets-refresh` (`Editor/Scripts/API/Tool/Assets.Refresh.cs:34-63`) calls `AssetDatabase.Refresh`, then branches only on `EditorApplication.isCompiling` (`:49`) and `EditorUtility.scriptCompilationFailed` (`:55`). There is no `EditorApplication.isPlaying` check. While the Editor is in Play mode, script edits are typically NOT recompiled until Play exits (depending on the "Script Changes While Playing" preference), so a caller that edits a `.cs` file then calls `assets-refresh` gets back `"AssetDatabase refreshed successfully."` (`:61`) even though the recompile was silently deferred — making any subsequent verification meaningless. The caller also can't query play state out-of-band: `editor-application-get-state` (`Editor/Scripts/API/Tool/Editor.Application.GetState.cs:33-39`), the one tool exposing `IsPlaying`/`IsCompiling` (sourced in `EditorStatsData.cs:53,55`), is registered with `Enabled = false` (`Editor.Application.GetState.cs:28`). The `AttachAutoRefreshWarning` helper (`Assets.Refresh.cs:71-85`) already populates `Metadata.warnings` as a `JsonArray` and is a natural hook for a Play-mode advisory. Minor: compile-failure detail is returned as a joined string via `GetCompilationErrorDetails()` (`:57-58`) rather than a structured `errors[]`.

**Workaround:** Exit Play mode before editing `.cs` files and calling `assets-refresh`, so the recompile actually runs and `isCompiling`/`scriptCompilationFailed` reflect the new code.
**Fix:** `assets-refresh` cannot detect that a *script* changed (`AssetDatabase.Refresh()` returns void; in the deferred case `isCompiling` stays false), so the implementable rule is: return a non-success `McpResponse.Error` with `statusReason: "compilation_deferred_play_mode"` (payload `recompiled:false`) **iff** `EditorApplication.isPlaying && EditorPrefs.GetInt("ScriptCompilationDuringPlay",0)==1 && !isCompiling` — i.e. only when the "Script Changes While Playing" preference is *Recompile After Finished Playing*, the one setting that silently defers the recompile. This never false-fails an asset-only refresh under the default preference; under that one preference it conservatively fails because the tool genuinely cannot distinguish asset-only from script edits (deliberate, per the hard-error directive below). Also enable `editor-application-get-state` (`Enabled=false`→true) for out-of-band `IsPlaying` discoverability, and return compile errors as a structured `errors[]` (shape shared with `CompileRequestState`) alongside the existing joined string.
