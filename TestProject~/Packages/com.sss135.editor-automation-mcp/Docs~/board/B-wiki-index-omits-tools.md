# Wiki root index served a partial namespace list, omitting enabled tools

Calling `mcp__editor-automation__call` with no `path` returned the root index ("Editor Automation — Method Reference / Auto-generated from the live tool registry") whose `## Namespaces` list contained ONLY `animation`, `animator`, `package`, `script`, `system`, `tests`. It omitted `assets`, `console`, and the other ~14 namespaces. The agent concluded `assets.refresh` / `console.get-logs` did not exist and hand-rolled workarounds (polling `EditorApplication.isCompiling`, reflecting `UnityEditor.LogEntries`).

The tools are real and enabled: `assets-refresh` (`Editor/Scripts/API/Tool/Assets.Refresh.cs:24-34`) and `console-get-logs` (`Console.GetLogs.cs:22-32`), on `[McpToolType]` classes `Tool_Assets` (`Assets.cs:16`) / `Tool_Console` (`Console.cs:17`); neither sets `Enabled=false`.

The generator is filter-free: `WikiMarkdownEmitter.RenderRootIndex` (`Framework/Wiki/WikiMarkdownEmitter.cs:123-182`) renders exactly the snapshot from `RpcDispatcher.RenderRootIndex` (`Http/RpcDispatcher.cs:642-658`), built from `ToolRegistry.NamespaceSummary()`/`MethodsInNamespace()` (`Framework/Builder/ToolRegistry.cs:256-283`). `Rebuild()` (`ToolRegistry.cs:119-156`) registers every scanned descriptor — no namespace filter, no `Enabled` filter. All `[McpToolType]` classes share one assembly (`com.SSS135.EditorAutomation.Editor.asmdef`). So a full index must list all namespaces; a 6-of-20 list means the single `Rebuild()` snapshot ran against a partially-loaded domain — `AttributeScanner.Scan` swallows `ReflectionTypeLoadException` and keeps only the types that loaded (`Framework/Builder/AttributeScanner.cs:84-89`), and `Rebuild` is fired once per reload from `FrameworkBootstrap`/`HttpGateway.cs:323` during recompile-heavy windows.

**Workaround:** Call methods by their exact dotted path (`assets.refresh`, `console.get-logs`) even when absent from the root index; read the per-namespace wiki page directly; re-fetch the index after the domain has fully settled.
**Fix:** The defect is that `ToolRegistry.Rebuild()` unconditionally commits whatever the scan produced — even a partial result — and nothing re-runs it once the domain finishes loading. Two swallow sites thin the snapshot: `AttributeScanner.Scan` keeps only `rtle.Types` on `ReflectionTypeLoadException`, and `Rebuild` silently `continue`s past any tool whose `new RunTool(descriptor)` throws during input-schema construction. Make the rebuild self-correcting rather than hardening one path: (a) count and log skipped tools / partial type loads at `Warning` so a thin snapshot is observable, and (b) subscribe `SafeRebuild` to `AssemblyReloadEvents.afterAssemblyReload` so the registry is re-snapshotted after every assembly is fully loaded — not only on the single `delayCall` that races domain warm-up. The wiki index is rebuilt live per request from the registry snapshot, so a corrected snapshot serves immediately with no cache to invalidate.

## History
- `#1-initial-repro` `OPEN` reporter — Root wiki (`mcp__editor-automation__call`, no `path`) listed only `animation`/`animator`/`package`/`script`/`system`/`tests`; `assets`+`console` (and ~12 more) were absent despite `assets-refresh` (`Assets.Refresh.cs:24`) and `console-get-logs` (`Console.GetLogs.cs:22`) being registered+enabled. Source has no namespace/Enabled filter (`ToolRegistry.cs:119-283`, `WikiMarkdownEmitter.cs:123-182`); the thin list points to a partial-domain `Rebuild()` snapshot (`AttributeScanner.cs:84-89`). Agent wasted the session reflecting `LogEntries` / polling `isCompiling` instead of calling the methods.
- `#2-self-correcting-rebuild` `IN-REVIEW` developer — Fixed in `FrameworkBootstrap.cs` (subscribe `SafeRebuild` to `AssemblyReloadEvents.afterAssemblyReload` so the registry re-snapshots after full assembly load, the load-bearing fix), `AttributeScanner.cs` (internal partial-load classifier seam + `Warning` log instead of silently keeping `rtle.Types`), and `ToolRegistry.cs` (skip counters + `Warning` when descriptors are dropped). Added regression test `Tests/Editor/Framework/Builder/AttributeScannerPartialLoadTests.cs` (new `com.SSS135.EditorAutomation.Editor.Tests` asmdef + `InternalsVisibleTo`) asserting the classifier reports a partial-load signal while preserving loaded types. Counterfactual: reverting the `AttributeScanner` change makes the assertion fail because the scan reports no partial-load signal even though a type failed to load. Note: the `afterAssemblyReload` re-Rebuild is Unity domain-reload lifecycle and is not unit-assertable; its correctness rests on documented `afterAssemblyReload` semantics.
